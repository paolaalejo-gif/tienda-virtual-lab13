1. RESUMEN DEL RESULTADO

LibroMundo es una primera versión funcional de un catálogo web para una librería que ofrece libros y útiles escolares. La pantalla obtiene los productos y categorías de una API Django REST Framework; el backend lee los registros de SQLite. El catálogo final tiene siete categorías y once productos.

El usuario puede consultar la lista, buscar por nombre o descripción, filtrar por categoría y abrir el detalle de un producto. La interfaz contempla estados de carga, error y reintento. No se incorporaron carrito, pedidos, pagos ni cuentas de clientes porque no forman parte del alcance de esta etapa.

3. ANÁLISIS FUNCIONAL Y DATOS DEL CATÁLOGO

Rubro: librería. Nombre: LibroMundo. El catálogo se organizó en Narrativa, Diseño, Bienestar, Infantil, Tecnología, Útiles escolares y Papel y escritura. Los once registros son La ciudad de las mareas, Cartas desde el sur, Diseñar con intención, Pequeños hábitos, grandes días, El jardín de los planetas, Interfaces que acompañan, Atlas de animales andinos, Código con propósito, Cuaderno de lectura A5, Marcadores de estudio y Agenda de lecturas.

Cada producto incluye nombre, descripción, precio decimal en soles, ruta pública de imagen, stock, categoría y marca de producto destacado. Las portadas ilustradas están en frontend/public/catalog/ como SVG locales y el campo image_url del backend apunta a dichas rutas. La tienda no depende de un servicio externo para esas portadas.

Requisitos comprobados en el equipo: Node.js v24.15.0, npm 11.1.0, Python 3.12.10 y Git 2.55.0. Para repetir la ejecución, abrir dos ventanas de PowerShell. En ambas, comenzar desde la carpeta raíz C:\Users\Paola\tienda-virtual-lab13. No cerrar la primera terminal mientras se usa la página.

Terminal 1 — preparar e iniciar Django:
  .\backend\.venv\Scripts\python.exe .\backend\manage.py migrate
  .\backend\.venv\Scripts\python.exe .\backend\manage.py seed_catalog
  .\backend\.venv\Scripts\python.exe .\backend\manage.py runserver 127.0.0.1:8000

La primera instrucción aplica las migraciones a SQLite. La segunda carga las siete categorías y once productos. Está diseñada para repetirse: crea o actualiza por slug de categoría y nombre de producto, por lo que permite restaurar los datos de ejemplo.

Terminal 2 — instalar dependencias e iniciar React:

  npm install
  npm run dev

Vite muestra la dirección local; normalmente es http://127.0.0.1:5173/. Abrirla en el navegador. Para detener los servidores, volver a cada terminal y presionar Ctrl+C.

5. CÓMO SE COMUNICAN LAS PARTES

Al abrir Storefront, el hook useEffect llama getCatalog. El servicio frontend/src/services/catalogService.js envía en paralelo dos solicitudes HTTP GET a /api/categories/ y /api/products/. Si la respuesta HTTP no es correcta, el servicio informa el error. La página guarda los arreglos y estados con useState; useMemo calcula los resultados visibles según el término de búsqueda y la categoría activa. AbortController cancela la petición si la página se desmonta.

Django REST Framework serializa los modelos y responde JSON. El endpoint GET http://127.0.0.1:8000/api/products/ entrega los atributos del producto y datos legibles de categoría. También se admite el filtro por categoría, por ejemplo /api/products/?category=1 (el identificador real depende de la base local). GET /api/categories/ lista categorías y recuentos; GET /api/health/ informa el estado del servicio.

La relación de datos es Category 1:N Product: una categoría puede agrupar varios productos y cada producto pertenece a una categoría. Product.category es una clave foránea protegida. Los campos de precio y stock tienen validaciones apropiadas para importes no negativos y existencias enteras no negativas.

6. ADMINISTRACIÓN DE PRODUCTOS

Los modelos Category y Product aparecen en http://127.0.0.1:8000/admin/. Para crear una cuenta administrativa propia, desde la raíz del proyecto:
  .\backend\.venv\Scripts\python.exe .\backend\manage.py createsuperuser

Seguir las preguntas de Django para definir usuario, correo opcional y contraseña; luego iniciar sesión en /admin/. En la sección Catálogo se pueden buscar y filtrar productos, consultar categoría, precio, stock y destacado, y abrir el formulario de un registro para actualizarlo.

Como comprobación funcional, se cambió desde el formulario de Django Admin el stock de Agenda de lecturas de 18 a 20. El listado mostró el mensaje de actualización y el valor 20. Después de consultar de nuevo la API, el catálogo de React reflejó “20 disponibles”. La carga seed_catalog.py también quedó con stock 20 para que el estado comprobado siga siendo reproducible. La cuenta temporal usada para tomar la evidencia fue eliminada; para futuras sesiones se debe crear un superusuario propio.

9. QUÉ QUEDA FUERA DEL ALCANCE Y CÓMO CONTINUAR

Esta versión es una práctica ejecutada en local con SQLite y servidores de desarrollo. No procesa compras. Para una tienda publicada se tendrían que implementar y asegurar autenticación de clientes, carrito, pedidos, pagos, manejo de secretos, base de producción, HTTPS y almacenamiento de imágenes.

El proyecto no tiene URL de GitHub publicada. No se creó una dirección ficticia ni se subió el código, porque no hay conexión GitHub disponible en esta sesión. Para cerrar ese punto de la rúbrica, publicar la carpeta raíz tienda-virtual-lab13 desde una cuenta/repositorio autorizado y añadir la URL real al informe.
